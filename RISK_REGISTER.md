## Decisions the owner must make before implementation

1. Approve core repairs and web launch gates before more feature phases.
2. Select discovery/geocoding provider approach using a known-place benchmark and realistic monthly traffic budget.
3. Restore permanent hosting and choose a canonical HTTPS origin without casually discarding the existing Site identity.
4. Choose guest/local-only native MVP versus account-and-sync MVP. Public login and sync have different gates.
5. Approve foreground-only location and a privacy/data-retention model suitable for the intended audience.

No risk is considered closed solely because a code path or button exists. Critical risks require successful runtime acceptance; live service/account/store risks require verification in the owner's actual environment.
